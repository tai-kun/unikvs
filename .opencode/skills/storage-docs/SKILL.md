# Storage Docs

UniKvs のストレージプラグイン（`IStorage` 実装）のドキュメントを、統一された構成で書く・直すための規約です。`transformer-docs` と同じ 4 構成に従います。

## 対象ファイル

- `website/content/ja/packages/(storage)/**/*.mdx`（(browser)・(bun)・(general)・(nodejs)・(wrapper) 配下）
- 仕様の根拠は `packages/<パッケージ名>/src/*.ts` から読み取ります。既存ドキュメントの記述を鵜呑みにしません。

## 全体構成

ページは次の見出しだけを持ちます。順序は固定です。

```md
## 概要 [#overview]

## 使い方 [#usage]

## データ型 [#data-types]

## エラー [#errors]
```

- 見出しには必ず `blume-docs` の規約どおりカスタム ID を付けます。
- 「エラー」の次に `## 注意事項 [#notes]` を置けますが、オプションです。非常にクリティカルなことがない限り付けません。
- フロントマターの `title`・`description` は維持します。
- ページ内リンクは `/packages/<name>` 形式にします（`/ja` 接頭辞は付けません）。

## 概要

- 1 文で概要を書きます（必須）。実行環境の限定がある場合のみ `<Badge variant="warning">Node.js 専用</Badge>`・`<Badge variant="warning">Bun 専用</Badge>`・`<Badge variant="warning">ブラウザー専用</Badge>` のいずれかを付けます。
- 用途を 1〜2 文で書きます（オプション）。
- 追加説明を箇条書きで書きます（オプション）。`name`・`isOpen`・`open`・`close` の要否、対応環境などの固定振る舞いを列挙します。
- 目立つ追加説明をコールアウトで書きます（オプション）。`:::tip`・`:::note`・`:::warning` を使い分けます。
- 末尾は必ず次の定型文のあとにインストールコマンドを置きます（必須）。

````md
インストールは次のコマンドで行います。

```package-install
npm install @unikvs/<name>
```
````

- ピア依存・外部サービスがある場合はコマンドに含めるか、直後に一文で補足します。

## 使い方

- 1 文で概要を書きます（必須）。次の定型文を一字一句変えずに使います。

```md
<クラス名> は IStorage を実装しています。UniKvs には persist() で渡します。
```

- `import` するだけのコードブロックを置きます（必須）。

```ts
import { Memory } from "@unikvs/memory";
```

- コンストラクターに引数がある場合のみ、「コンストラクターの引数は次のとおりです。」のあとに引数を `TypeTable` コンポーネントで書きます（オプション）。引数なしのクラスではこの一文ごと省略します。内部ストレージをラップするクラス（`WriteOnly` など）は委譲先の `storage` を第一引数として記載します。
- UniKvs を使った使用例だけを書きます。単体での直接操作の例は不要です（必須）。`open`・`close` が必要なストレージは使用例に含めます。
- 使用例のコードブロックの直前には「以下は、〜する例です。」の導入文を置きます。コードブロック直後の重複した説明文は付けません。

````md
以下は、値を保存して読み戻す例です。

```ts
import { Memory } from "@unikvs/memory";
import UniKvs, { type PlainValue } from "unikvs";
...
```
````

## データ型

- `write`・`read` に対応する値の型と、対応していればストリーム（`getWritable`・`getReadable`）のチャンクの型を表で記載します（必須）。入出力の型ではなく、対応するデータ型を書きます。データ型はパッケージに合わせて変えます（例: `@unikvs/memory` は任意の値、`@unikvs/localstorage` は文字列、バイト列専用ストレージは `Uint8Array<ArrayBuffer>`）。

```md
| 操作                                    | 対応するデータ型                     |
| --------------------------------------- | ------------------------------------ |
| `write`・`read`                         | 任意の値（文字列・オブジェクトなど） |
| `getWritable`・`getReadable` のチャンク | `Uint8Array<ArrayBuffer>`            |
```

- どのようなデータが保存できるのかを箇条書きで説明します（必須）。段落で書かないでください。
- ストリームの扱い（対応有無・チャンク型・分割の可否など）を箇条書きで説明します（オプション）。段落で書かないでください。

## エラー

- パッケージ固有のエラーがある場合のみ、先頭に次の定型文を置きます（必須）。ない場合は定型文も置きません。

```md
このパッケージが投げるエラーは次のとおりです。
```

- エラーごとに `### <エラークラス>` 見出しを置き、`#### 意味`（必須）・`#### 対処方法`（必須）・`#### 例`（オプション）の小見出しで分けます。

````md
### KeyNotFoundError

#### 意味

指定したキーが存在しません。`@unikvs/core` の共通エラーです。

#### 対処方法

`exists` で確認してから読み出してください。

#### 例

以下は、`KeyNotFoundError` を捕捉する例です。

```ts
...
```
````

- `#### 例` はどのようなコードでエラーが出るかを示す場合のみ付けます。形式は「以下は、`<エラー>` を捕捉する例です。」＋コードブロックです。
- `@unikvs/core` の共通エラー（`KeyNotFoundError` など）も投げる場合は `###` で記載し、意味に共通エラーである旨を含めます。
- パッケージ固有のエラーがない場合は定型文も `###` 見出しも作らず、「このパッケージ固有のエラーはありません。」と書き、該当すれば共通エラーの扱いを一文で補足します。

## 仕様の調べ方

型・振る舞い・エラーは `packages/<name>/src` から読み取ります。

| 確認対象                                                            | 読み取り箇所                                               |
| ------------------------------------------------------------------- | ---------------------------------------------------------- |
| クラス名・コンストラクター引数                                      | クラス定義と `*Options` 型                                 |
| `write`・`read`・`exists`・`delete`・`clear` の入出力・同期／非同期 | メソッドシグネチャー                                       |
| ストリームの対応有無・チャンク型                                    | `getWritable`・`getReadable` の有無と型                    |
| エラークラス・送出条件                                              | `errors.ts` と `throw` 箇所（共通エラーは `@unikvs/core`） |
| `name`・`isOpen`・`open`・`close` の要否、ピア依存                  | クラス定義と `package.json`                                |

## 検証

- `website` ディレクトリーで `npx blume validate` を実行し、リンク切れがないことを確認します。
- `website` ディレクトリーで `npx blume build --isolated` を実行し、ビルドが成功することを確認します。

## ガイドライン

### 推奨

- 定型文は一字一句変えずに使います。
- 使用例・エラーの例の前には必ず「以下は、〜する例です。」／「以下は、`<エラー>` を捕捉する例です。」を置きます。
- データ型の説明文は箇条書きにし、段落で書かないでください。
- 文章は `japanese`・`natural-japanese` スキルに従い、簡潔に書きます。

### 非推奨

- 全体構成以外の見出し（ファイル配置・キーの配置・ストリーム・使用例・注意点など）を追加しないでください。配置や内部形式の説明は「データ型」の箇条書きに含めます。
- 単体での直接操作の例を「使い方」に書かないでください（エラーの「例」を除く）。
- データ型を `TypeTable` で書かないでください。表を使います。
