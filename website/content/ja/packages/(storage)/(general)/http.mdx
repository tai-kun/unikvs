## 概要 [#overview]

`@unikvs/http` は、任意の HTTP エンドポイントを KV として使うストレージプラグインです。

Edge や Workers などの最小ランタイムで動作し、`fetch` だけで読み書きします。

- `name` は常に `"Http"` を返し、`isOpen` は常に `true` です。`open`・`close` は中断の検証だけを行い、接続は作りません。
- 扱うデータはバイト列専用です。キーは `baseUrl` 直下の単一セグメントに対応します。
- すべてのキーに `keyPrefix` を付けて保存します。既定値は `"unikvs:"` です。

:::warning
`clear` は `DELETE ?prefix=` に対応するサーバー実装が必要です。対応しないサーバーでは使えません。
:::

インストールは次のコマンドで行います。

```package-install
npm install @unikvs/http
```

接続先の HTTP サーバーは別途用意してください。

## 使い方 [#usage]

Http は IStorage を実装しています。UniKvs には persist() で渡します。

```ts
import { Http } from "@unikvs/http";
```

コンストラクターの引数は次のとおりです。

以下は、値を保存して読み戻す例です。

```ts
import { Http } from "@unikvs/http";
import { UniKvs, type Value } from "unikvs";

const kvs = UniKvs.config<{
  greeting: Value<Uint8Array<ArrayBuffer>>;
}>()
  .persist(new Http("https://kv.example.com/store"))
  .create();

await kvs.open();

await kvs.set("greeting", new TextEncoder().encode("hello"));
const greeting = await kvs.get("greeting");

await kvs.close();
```

## データ型 [#data-types]

| 操作                                    | 対応するデータ型          |
| --------------------------------------- | ------------------------- |
| `write`・`read`                         | `Uint8Array<ArrayBuffer>` |
| `getWritable`・`getReadable` のチャンク | `Uint8Array<ArrayBuffer>` |

- `write`・`read` はバイト列だけに対応し、`PUT` と `GET` で送受信します。
- キーは `` `${baseUrl}/${encoded}` `` に対応します。`encoded` は `` `${keyPrefix}${key}` `` を符号化した単一セグメントで、`.` は `%2E` に変換します。
- `clear` は `DELETE ?prefix=` だけを使い、接頭辞に一致するデータを削除します。
- ストリーム操作は `Uint8Array<ArrayBuffer>` だけに対応しています。
- `getWritable` はチャンクをメモリーに蓄積し、`close` 時に一括で `PUT` します。
- `getReadable` は応答のボディーをそのまま返します。ボディーがない応答では空ストリームを返します。

## エラー [#errors]

このパッケージが投げるエラーは次のとおりです。

### KeyNotFoundError

#### 意味

指定したキーが存在しません。`@unikvs/core` の共通エラーです。

#### 対処方法

`exists` で確認してから読み出すか、キーの指定誤りを確認してください。

#### 例

以下は、`KeyNotFoundError` を捕捉する例です。

```ts
import { Http, KeyNotFoundError } from "@unikvs/http";

const storage = new Http("https://kv.example.com/store");

try {
  await storage.read({ key: "missing.bin", vars: {} });
} catch (error) {
  if (error instanceof KeyNotFoundError) {
    console.log(error.meta.key);
  } else {
    throw error;
  }
}
```

### InvalidBaseUrlError

#### 意味

`baseUrl` が絶対 URL ではありません。相対 URL や空文字、クエリー・フラグメント付きが原因です。

#### 対処方法

クエリーやフラグメントのない絶対 URL を指定してください。末尾の `/` は自動で除去します。

### InvalidHeadersError

#### 意味

ヘッダーに文字列以外の値が含まれています。`meta` に `actual` を含みます。

#### 対処方法

ヘッダーの値は文字列だけで指定してください。

### InvalidTokenError

#### 意味

トークンが空文字か文字列以外です。`meta` に `actual` を含みます。

#### 対処方法

空でない文字列を指定するか、トークンを使わない場合は省略してください。

### InvalidKeyError

#### 意味

キーを URL パスセグメントに符号化できません。`meta` に `key` を含みます。

#### 対処方法

符号化できるキーに変えてください。

### ClearWithoutPrefixNotAllowedError

#### 意味

空の `keyPrefix` のまま許可なく `clear` を呼びました。

#### 対処方法

一意な `keyPrefix` を指定するか、`allowClearWithoutPrefix: true` を指定してください。

### ClearNotSupportedError

#### 意味

サーバーが `DELETE ?prefix=` に対応していません。`meta` に `prefix` と `status` を含みます。

#### 対処方法

サーバー側で一括削除に対応するか、`clear` を使わない運用にしてください。

### HttpNetworkError

#### 意味

送信自体に失敗しました。`meta` に `method`・`url`・`key` を含みます。

#### 対処方法

接続先とネットワークの状態を確認し、必要なら再試行してください。

### HttpResponseError

#### 意味

応答が異常ステータスです。`meta` に `method`・`url`・`status`・`statusText`・`key` を含みます。

#### 対処方法

状態コードに応じて要求とサーバーの実装を確認してください。

### InvalidChunkTypeError

#### 意味

チャンクの型が `Uint8Array<ArrayBuffer>` ではありません。`meta` に `key`・`chunk`・`chunkType` を含みます。

#### 対処方法

ストリームには `Uint8Array<ArrayBuffer>` だけを流してください。
