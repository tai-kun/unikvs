## 概要 [#overview]

`@unikvs/writeonly` は、既存のストレージを書き込み専用にラップするストレージプラグインです。

改変や削除を防ぎたいバックアップの保管に使います。

- `name` は常に `"WriteOnly"` を返し、`isOpen`・`open`・`close` は内部ストレージへ委譲します。
- 書き込みは内部ストレージへそのまま委譲し、読み出しは常に失敗します。
- `delete`・`clear` は既定で何もせず、`allowDelete` で許可できます。

インストールは次のコマンドで行います。

```package-install
npm install @unikvs/writeonly
```

## 使い方 [#usage]

WriteOnly は IStorage を実装しています。UniKvs には persist() で渡します。

```ts
import { WriteOnly } from "@unikvs/writeonly";
```

コンストラクターの引数は次のとおりです。

<TypeTable
  type={{
    storage: {
      type: "IStorage",
      description: "書き込みを委譲する内部ストレージです。",
    },
    options: {
      type: "WriteOnlyOptions",
      description: "削除の許可の設定です。省略時は既定値で動作します。",
    },
    "options.allowDelete": {
      type: "boolean",
      default: "false",
      description: "`delete`・`clear` を内部ストレージへ委譲するかどうかです。",
    },
  }}
/>

以下は、読み出し用のストレージと書き込み専用のアーカイブを併用する例です。

```ts
import { NodeFs } from "@unikvs/fs.node";
import { WriteOnly } from "@unikvs/writeonly";
import { UniKvs, type Value } from "unikvs";

const kvs = UniKvs.config<{
  report: Value<Uint8Array<ArrayBuffer>>;
}>()
  .persist(new NodeFs(".data"))
  .persist(new WriteOnly(new NodeFs(".archive")))
  .create();

await kvs.open();

await kvs.set("report", new Uint8Array([1, 2, 3]));
const report = await kvs.get("report");

await kvs.close();
```

## データ型 [#data-types]

| 操作                     | 対応するデータ型                   |
| ------------------------ | ---------------------------------- |
| `write`                  | 内部ストレージが対応するデータ型   |
| `getWritable` のチャンク | 内部ストレージが対応するチャンク型 |

- 書き込みは内部ストレージへそのまま委譲するため、対応するデータ型は内部ストレージに従います。
- `read` には対応しません。呼び出すと常に `KeyNotFoundError` を投げます。
- `exists` は常に `false` を返します。
- `getWritable` は内部ストレージが対応する場合だけ公開し、チャンク型も内部ストレージに従います。
- `getReadable` には対応しません。呼び出すと常に `KeyNotFoundError` を投げます。

## エラー [#errors]

このパッケージ固有のエラーはありません。`read`・`getReadable` は常に `@unikvs/core` の `KeyNotFoundError` を投げます。
