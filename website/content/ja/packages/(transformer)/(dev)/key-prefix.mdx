## 概要 [#overview]

`@unikvs/key-prefix` は、すべてのキーに固定文字列を付与する Transformer プラグインです。<Badge>Transformer</Badge>

開発環境と本番環境で保存先を使い分けたい場合や、1 つの保存先を複数のテナントで共有する場合に使います。たとえば `dev:` や `prod:`、テナントごとの接頭辞を付けてキーを分離できます。

- データは変換せず、キーの先頭に `prefix` を付けるだけです。
- 常にオープン状態です。`open`・`close` は不要で、`isOpen` は常に `true`、`name` は常に `"KeyPrefix"` を返します。
- `prefix` と `clearBehavior`（既定 `"allow"`）は構築時に確定し、あとから変更できません。`prefix` に `""` を渡すとキーを変えずに透過します。

:::warning
`clear` は接頭辞の範囲に限定されず、保存先の全件を削除します。保存先を共有している場合は他のテナントのデータまで削除されるため、占有を保証できない場合は `clearBehavior: "deny"` を指定するか、保存先の実体を分けてください。
:::

インストールは次のコマンドで行います。

```package-install
npm install @unikvs/key-prefix
```

## 使い方 [#usage]

KeyPrefix は ITransformer を実装しています。UniKvs には transform() で渡します。

```ts
import { KeyPrefix } from "@unikvs/key-prefix";
```

コンストラクターの引数は次のとおりです。

<TypeTable
  type={{
    prefix: {
      type: "string",
      required: true,
      description:
        'すべてのキーの先頭に付ける文字列です。必須です。省略すると型エラーになります。`""` を渡すとキーを変えずに透過します。',
    },
    options: {
      type: "KeyPrefixOptions",
      description:
        '`clear` の挙動を設定します。省略時は `clearBehavior: "allow"` として動作します。',
    },
    "options.clearBehavior": {
      type: '"allow" | "deny"',
      default: '"allow"',
      description:
        '`clear` 時の挙動です。`"allow"` では保存先の全件を削除し、`"deny"` ではエラーを投げて削除を拒否します。不正な値は構築時に `InvalidClearBehaviorError` を投げます。',
    },
  }}
/>

以下は、すべてのキーに `tenant:` を付けて保存する例です。

```ts
import { KeyPrefix } from "@unikvs/key-prefix";
import { Memory } from "@unikvs/memory";
import { UniKvs, type PlainValue } from "unikvs";

const kvs = UniKvs.config<{ greeting: PlainValue<string> }>()
  .connect(new KeyPrefix("tenant:"))
  .persist(new Memory())
  .create();

await kvs.open();

await kvs.set("greeting", "hello");
const greeting = await kvs.get("greeting");

await kvs.close();
```

## データ型 [#data-types]

| メソッド       | 入力    | 出力    |
| -------------- | ------- | ------- |
| `encode`       | `TData` | `TData` |
| `decode`       | `TData` | `TData` |
| `getEncodable` | `any`   | `any`   |
| `getDecodable` | `any`   | `any`   |

- `encode`・`decode` は任意の型のデータをそのまま返します。
- `getEncodable`・`getDecodable` はチャンクをそのまま流す `TransformStream` を返します。
- 値の変換は行わず、キーは論理キーの先頭に `prefix` を付けた物理キーで保存し、元に戻す変換はありません。
- データの内容にもチャンクの分割にも影響しません。
- チャンクは区切り文字なしで単純に透過します。

## エラー [#errors]

このパッケージが投げるエラーは次のとおりです。

### KeyPrefixClearNotSupportedError

#### 意味

`prefix` が空文字ではなく、`clearBehavior` が `"deny"` の場合、`clear` は範囲限定削除を保証できないため失敗します。`meta` に `prefix` と `clearBehavior` を含みます。

#### 対処方法

単一テナントで保存先を占有できる場合は `clearBehavior` に `"allow"` を指定するか、保存先の実体を分けてください。

### InvalidClearBehaviorError

#### 意味

`clearBehavior` が `"allow"` と `"deny"` のいずれでもない場合に発生します。`meta` に `actual` を含みます。エラーの `name` は `KeyPrefixInvalidClearBehaviorError` です。

#### 対処方法

`clearBehavior` に `"allow"` または `"deny"` を指定するか、省略して既定値（`"allow"`）を使ってください。

## 注意事項 [#notes]

- `clear` は既定で保存先の全件を削除します。占有を保証できない場合は `clearBehavior: "deny"` を指定するか、保存先の実体を分けてください。
- 接頭辞の範囲だけを削除する `clear` はできません。
- 常に論理キーを渡してください。接頭辞を含むキーを渡すと二重に付与されます。
- Redis の `keyPrefix` と組み合わせると接頭辞が二重に付きます（例: `tenant:unikvs:k1`）。併用する場合はどちらか一方を空にしてください。
- `prefix` が `""` の場合、`clearBehavior` に関わらず `clear` をそのまま委譲します。
- 存在しないキーの `KeyNotFoundError` の `meta.key` は接頭辞なしの論理キーです。ただし `cause` やログには接頭辞付きのキーが残る場合があります。
- `clear` を拒否する設定が複数ある場合、最初に検出した設定が報告され、保存先の削除は実行されません。
- `prefix` の型チェックは TypeScript で行います。JavaScript から非文字列を渡した場合の動作は保証されません。
