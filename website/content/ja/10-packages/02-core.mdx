## 概要 [#overview]

`@unikvs/core` は、unikvs の全パッケージで共有される型定義と基底エラーを提供するパッケージです。ストレージ (`IStorage`) やトランスフォーマー (`ITransformer`) のインターフェース、実行時変数 (`Variables`)、エラー基盤 (`ErrorBase`) がここに集約されています。

プラグインや上位パッケージは、このパッケージで定義された契約に沿って実装されます。そのため、ストレージやトランスフォーマーの自作プラグインを作成する場合を除き、通常はこのパッケージを直接触る必要はありません。

インストールは次のコマンドで行います。

```package-install
pnpm add @unikvs/core
```

`src/index.ts` では、次の内容が再エクスポートされています。

```ts
export type * from "./variables.types.js";
export type { ErrorMeta, ErrorOptions } from "./errors.js";
export { ErrorBase, setErrorMessage, InvalidUsageErrorBase } from "./errors.js";
export type * from "./storage.types.js";
export type * from "./transformer.types.js";
```

## Storageインターフェース [#storage]

ストレージの契約は `src/storage.types.ts` で定義されています。中心となるのは総合インターフェース `IStorage` です。単発の読み書きに加えて、ストリームベースの大規模データ処理も同じインターフェースで扱います。

### 型パラメーター [#storage-type-params]

`IStorage` は 4 つの型パラメーターを持ちます。

```ts
export interface IStorage<
  TWriteDataInput = any,
  TReadDataOutput = TWriteDataInput,
  TWriteChunkInput = TWriteDataInput extends ArrayBufferLike | ArrayBufferView
    ? TWriteDataInput
    : any,
  TReadChunkOutput = TWriteChunkInput,
>
```

それぞれの意味は次のとおりです。

| 型パラメーター | 意味 |
| --- | --- |
| `TWriteDataInput` | `write` で書き込む入力データの型です。 |
| `TReadDataOutput` | `read` で取得する出力データの型です。既定値は `TWriteDataInput` です。 |
| `TWriteChunkInput` | ストリーム書き込み時の入力チャンク型です。書き込みデータが `ArrayBufferLike` または `ArrayBufferView` の場合はその型が既定値となり、それ以外は `any` が既定値となります。 |
| `TReadChunkOutput` | ストリーム読み取り時の出力チャンク型です。既定値は `TWriteChunkInput` です。 |

### ライフサイクル [#storage-lifecycle]

`IStorage` は次のプロパティーとオプショナルメソッドを持ちます。

```ts
readonly name: string;
readonly isOpen: boolean;
open?(args: IStorage.OpenArgs): MaybePromise<void>;
close?(args: IStorage.CloseArgs): MaybePromise<void>;
onOtherWriteError?(args: IStorage.OnOtherWriteErrorArgs): MaybePromise<void>;
```

`name` はデバッグメッセージなどに使用されるストレージ名です。`isOpen` は現在利用可能な状態であるかを示します。

`open` はデータベース接続の確立やファイルシステムの初期化など、読み書き前の準備を行います。`close` は未書き込みデータのフラッシュやコネクションの切断など、安全な終了処理を行います。どちらもオプショナルであり、戻り値は `MaybePromise<void>` です。

<Steps>
  <Step title="open で準備します">データベース接続の確立やファイルシステムの初期化など、読み書き前の準備を行います。</Step>
  <Step title="読み書きを行います">CRUD 操作やストリーム取得など、必要なデータ操作を行います。</Step>
  <Step title="close で終了します">未書き込みデータのフラッシュやコネクションの切断など、安全な終了処理を行います。</Step>
</Steps>

`onOtherWriteError` もオプショナルです。自身以外のストレージがエラーを投げた場合の後処理を行い、必要に応じてデータを削除できます。引数には集約されたエラーが `ErrorBase` として渡されます。

引数の型は名前空間 `IStorage` に定義されています。

```ts
export type OpenArgs = {
  vars: Variables;
  signal: AbortSignal;
};

export type CloseArgs = {
  vars: Variables;
  signal: AbortSignal;
};
```

<Expandable title="OnOtherWriteErrorArgs の全体像を見る">
`OnOtherWriteErrorArgs` は `vars` と `key`、`signal` に加えて、集約されたエラーを `error` に保持します。`error` のメタ情報には、書き込み操作に関する集約内容が格納されます。

```ts
export type OnOtherWriteErrorArgs = {
  vars: Variables;
  key: Key;
  error: ErrorBase<{
    readonly plugin: "storage";
    readonly action: "write";
    readonly errors: readonly {
      readonly plugin: "storage";
      readonly reason: unknown;
    }[];
  }>;
  signal: AbortSignal;
};
```
</Expandable>

### CRUD操作 [#storage-crud]

必須の CRUD メソッドは次の 5 つです。戻り値はすべて `MaybePromise` であり、同期値または `Promise` のどちらでも返すことができます。

```ts
write(args: IStorage.WriteArgs<TWriteDataInput>): MaybePromise<void>;
read(args: IStorage.ReadArgs): MaybePromise<TReadDataOutput>;
exists(args: IStorage.ExistsArgs): MaybePromise<boolean>;
delete(args: IStorage.DeleteArgs): MaybePromise<void>;
clear(args: IStorage.ClearArgs): MaybePromise<void>;
```

それぞれの引数型は次のとおりです。すべての操作に `vars: Variables` と `signal: AbortSignal` が含まれます。

```ts
export type Key = string;

export type WriteArgs<TData = any> = {
  vars: Variables;
  key: Key;
  data: TData;
  signal: AbortSignal;
};

export type ReadArgs = {
  vars: Variables;
  key: Key;
  signal: AbortSignal;
};

export type ExistsArgs = {
  vars: Variables;
  key: Key;
  signal: AbortSignal;
};

export type DeleteArgs = {
  vars: Variables;
  key: Key;
  signal: AbortSignal;
};

export type ClearArgs = {
  vars: Variables;
  signal: AbortSignal;
};
```

`Key` は `string` の別名です。`ClearArgs` のみ `key` を持たず、ストレージ内のすべてのデータを消去します。

### ストリーム対応 [#storage-streams]

ストリーム機能はオプショナルです。`IStorage` は次の 2 つのインターフェースを `Partial` で継承するため、対応しないストレージは実装を省略できます。

```ts
export interface IWritableStream<TData = any> extends WritableStream<TData> {}
export interface IReadableStream<TData = any> extends ReadableStream<TData> {}

export interface IWritableStreamStorage<TData = any> {
  getWritable(args: IStorage.GetWritableArgs): MaybePromise<IWritableStream<TData>>;
}

export interface IReadableStreamStorage<TData = any> {
  getReadable(args: IStorage.GetReadableArgs): MaybePromise<IReadableStream<TData>>;
}
```

ストリーム取得時の引数は次のとおりです。

```ts
export type GetWritableArgs = {
  vars: Variables;
  key: Key;
  signal: AbortSignal;
};

export type GetReadableArgs = {
  vars: Variables;
  key: Key;
  signal: AbortSignal;
};
```

ストリームに対応するかどうかは実装側の取り決めに委ねられています。対応する場合は `getWritable` または `getReadable` を実装し、対応しない場合は省略します。呼び出し側はメソッドの有無を確認して利用する必要があります。

<Expandable title="IStorage のストリーム継承定義を見る">
`IStorage` は書き込み用と読み取り用のストリーム機能を `Partial` で継承しています。そのため、対応しないストレージは `getWritable` や `getReadable` を省略できます。

```ts
export interface IStorage<
  TWriteDataInput = any,
  TReadDataOutput = TWriteDataInput,
  TWriteChunkInput = TWriteDataInput extends ArrayBufferLike | ArrayBufferView
    ? TWriteDataInput
    : any,
  TReadChunkOutput = TWriteChunkInput,
>
  extends
    Partial<IWritableStreamStorage<TWriteChunkInput>>,
    Partial<IReadableStreamStorage<TReadChunkOutput>> {
  readonly name: string;
  readonly isOpen: boolean;
}
```
</Expandable>

## Transformerインターフェース [#transformer]

トランスフォーマーの契約は `src/transformer.types.ts` で定義されています。中心となるのは双方向変換を管理する総合インターフェース `ITransformer` です。単発のデータ変換とストリームベースの変換の両方をサポートします。

### 型パラメーター [#transformer-type-params]

`ITransformer` は 8 つの型パラメーターを持ちます。すべて既定値は `any` です。

```ts
export interface ITransformer<
  TEncodeDataInput = any,
  TDecodeDataInput = any,
  TEncodeDataOutput = any,
  TDecodeDataOutput = any,
  TEncodeChunkInput = any,
  TDecodeChunkInput = any,
  TEncodeChunkOutput = any,
  TDecodeChunkOutput = any,
>
```

前半 4 つは単発の `encode` と `decode` における入出力データの型、後半 4 つはストリーム変換時の入出力チャンクの型です。

### ライフサイクル [#transformer-lifecycle]

`ITransformer` は次のプロパティーとオプショナルメソッドを持ちます。

```ts
readonly name: string;
readonly isOpen: boolean;
open?(args: ITransformer.OpenArgs): MaybePromise<void>;
close?(args: ITransformer.CloseArgs): MaybePromise<void>;
```

`name` はデバッグメッセージなどに使用される名前です。`isOpen` は現在利用可能な状態であるかを示します。`open` はリソースの確保や外部接続の初期化、`close` は確保したリソースの解放や接続の終了処理を行います。どちらもオプショナルです。

```ts
export type OpenArgs = {
  vars: Variables;
  signal: AbortSignal;
};

export type CloseArgs = {
  vars: Variables;
  signal: AbortSignal;
};
```

### 単発変換 [#transformer-once]

単発のエンコードとデコードは必須メソッドです。

```ts
encode(args: ITransformer.EncodeArgs<TEncodeDataInput>): MaybePromise<TEncodeDataOutput>;
decode(args: ITransformer.DecodeArgs<TDecodeDataInput>): MaybePromise<TDecodeDataOutput>;
```

```ts
export type EncodeArgs<TData = any> = {
  vars: Variables;
  data: TData;
  signal: AbortSignal;
};

export type DecodeArgs<TData = any> = {
  vars: Variables;
  data: TData;
  signal: AbortSignal;
};
```

### ストリーム変換 [#transformer-streams]

ストリーム変換はオプショナルです。`ITransformer` は次の 2 つのインターフェースを `Partial` で継承します。

```ts
export interface IEncodable<TChunkInput = any, TChunkOutput = any> extends TransformStream<
  TChunkInput,
  TChunkOutput
> {}

export interface IDecodable<TChunkInput = any, TChunkOutput = any> extends TransformStream<
  TChunkInput,
  TChunkOutput
> {}

export interface IEncodableStreamTransformer<TChunkInput = any, TChunkOutput = any> {
  getEncodable(
    args: ITransformer.GetEncodableArgs,
  ): MaybePromise<IEncodable<TChunkInput, TChunkOutput>>;
}

export interface IDecodableStreamTransformer<TChunkInput = any, TChunkOutput = any> {
  getDecodable(
    args: ITransformer.GetDecodableArgs,
  ): MaybePromise<IDecodable<TChunkInput, TChunkOutput>>;
}
```

`IEncodable` と `IDecodable` はどちらも `TransformStream` を継承し、ストリーミングパイプラインの一部として機能します。引数の型は次のとおりです。

```ts
export type GetEncodableArgs = {
  vars: Variables;
  signal: AbortSignal;
};

export type GetDecodableArgs = {
  vars: Variables;
  signal: AbortSignal;
};
```

### 実装時の注意 [#transformer-notes]

実装時には次の点に注意します。

- `encode` と `decode` は必須ですが、`getEncodable` と `getDecodable` は任意です。ストリーム変換が不要な実装では省略できます。
- すべてのメソッドの引数に `vars: Variables` と `signal: AbortSignal` が含まれます。処理の中断には `signal` を使用します。
- 戻り値はすべて `MaybePromise` です。同期的に値を返すことも、`Promise` を返すこともできます。

## 変数の型 [#variables]

`src/variables.types.ts` では、unikvs 内で状態や設定を保持するための汎用的な変数オブジェクトの型 `Variables` が定義されています。

```ts
export type Variables = Record<string, unknown>;
```

キーは `string`、値は `unknown` として扱われます。ストレージとトランスフォーマーのすべての引数型に `vars: Variables` が含まれており、実行時のコンテキストや設定値を受け渡すために使用されます。

使用例は次のとおりです。

```ts
import type { Variables } from "@unikvs/core";

const vars: Variables = {
  locale: "ja",
  retryCount: 3,
};
```

## エラー基盤 [#errors]

エラー基盤は `src/errors.ts` で定義されています。すべての unikvs 固有エラーはここから派生します。

### ErrorBase [#errors-base]

```ts
export class ErrorBase<
  TMeta extends ErrorMeta | undefined = ErrorMeta | undefined,
> extends I18nErrorBase<TMeta> {}
```

`ErrorBase` は unikvs のすべてのエラーの基底クラスです。`i18n-error-base` パッケージの `I18nErrorBase` を継承しており、言語ごとのメッセージ切り替えに対応しています。型パラメーター `TMeta` でエラーが保持するメタ情報の型を指定します。

:::note
`ErrorBase` は `i18n-error-base` の `I18nErrorBase` を継承しているため、メッセージは言語ごとに切り替わります。自作プラグインでは、利用される言語ごとのメッセージを `setErrorMessage` で登録されることをおすすめします。
:::

関連する型も再エクスポートされています。

```ts
export type { ErrorMeta };
export type { ErrorOptions };
```

`ErrorMeta` はキーを `string`、値を `unknown` として扱う読み取り専用オブジェクトの型です。`ErrorOptions` はエラーのコンストラクターに渡せるオプションの型であり、`cause` で原因となった値を保持できます。

### setErrorMessage [#errors-message]

```ts
export { setErrorMessage };
```

`setErrorMessage` はエラークラスに言語ごとのメッセージを登録する関数であり、`i18n-error-base` からの再エクスポートです。登録できるメッセージは固定文字列か、メタ情報を受け取って文字列を返す関数です。言語は 1 つの言語タグか、複数の言語タグを列挙した反復可能オブジェクトで指定します。

```ts
import { MyPluginError, setErrorMessage } from "@unikvs/core";

setErrorMessage(MyPluginError, "データの読み取りに失敗しました。", "ja");
setErrorMessage(MyPluginError, "Failed to read data.", "en");
```

### InvalidUsageErrorBase [#errors-invalid-usage]

```ts
export class InvalidUsageErrorBase<
  TMeta extends ErrorMeta | undefined = ErrorMeta | undefined,
> extends ErrorBase<TMeta> {}
```

`InvalidUsageErrorBase` は無効な使用方法、すなわち API 契約違反を示すエラーの基底クラスです。引数の不備や利用手順の誤りなど、呼び出し側の使い方に問題がある場合に使用されます。

### 独自プラグインでのエラー定義 [#errors-custom]

独自プラグインでエラーを定義する際の要点は次のとおりです。

1. `ErrorBase` または `InvalidUsageErrorBase` を継承したクラスを作成します。契約違反を表す場合は `InvalidUsageErrorBase` を選びます。
2. 必要に応じて `TMeta` にメタ情報の型を指定し、メッセージ生成に必要な情報を保持します。
3. `setErrorMessage` で言語ごとのメッセージを登録します。メタ情報に応じた動的メッセージが必要な場合は関数を渡します。

:::tip
契約違反を表すエラーには `InvalidUsageErrorBase` を選ばれますと、呼び出し側の使い方に問題があることが伝わりやすくなります。動的メッセージが必要な場合は、メタ情報を受け取る関数を `setErrorMessage` に渡されますと、`key` などの情報を含めた文面を作成できます。
:::

```ts
import { ErrorBase, setErrorMessage } from "@unikvs/core";

type MyMeta = {
  readonly key: string;
};

export class MyStorageError extends ErrorBase<MyMeta> {}

setErrorMessage(MyStorageError, (meta) => `キー ${meta.key} の書き込みに失敗しました。`, "ja");
setErrorMessage(MyStorageError, (meta) => `Failed to write key ${meta.key}.`, "en");
```

## サブパスエクスポート [#exports]

`package.json` の `exports` には 3 つのエントリーポイントが定義されています。

```json
{
  "exports": {
    ".": {
      "types": "./dist/src/index.d.ts",
      "default": "./dist/src/index.js"
    },
    "./storage": {
      "types": "./dist/src/storage.types.d.ts",
      "default": "./dist/src/storage.types.js"
    },
    "./transformer": {
      "types": "./dist/src/transformer.types.d.ts",
      "default": "./dist/src/transformer.types.js"
    }
  }
}
```

使い分けの目安は次のとおりです。

<Tabs>
  <Tab title="@unikvs/core">
すべてを利用する場合のエントリーポイントです。`Variables`、`ErrorBase`、`setErrorMessage`、`InvalidUsageErrorBase`、`IStorage`、`ITransformer` をまとめて取得できます。

```ts
import { ErrorBase, type IStorage, type Variables } from "@unikvs/core";
```
  </Tab>
  <Tab title="@unikvs/core/storage">
ストレージの型のみが必要な場合に利用します。`IStorage`、`IWritableStream`、`IReadableStream`、`IWritableStreamStorage`、`IReadableStreamStorage` が含まれます。

```ts
import type { IStorage, IWritableStreamStorage } from "@unikvs/core/storage";
```
  </Tab>
  <Tab title="@unikvs/core/transformer">
トランスフォーマーの型のみが必要な場合に利用します。`ITransformer`、`IEncodable`、`IDecodable`、`IEncodableStreamTransformer`、`IDecodableStreamTransformer` が含まれます。

```ts
import type { ITransformer, IEncodableStreamTransformer } from "@unikvs/core/transformer";
```
  </Tab>
</Tabs>
