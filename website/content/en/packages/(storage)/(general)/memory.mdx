## Overview [#overview]

`@unikvs/memory` is a storage plugin that keeps data in memory.

Use it for test doubles and temporary caches.

- Reads and writes finish synchronously, with no `open` or `close` needed. `isOpen` always returns `true` and `name` always returns `"Memory"`.
- Strings, objects, and other arbitrary values can be stored as-is.
- Values are cloned on write and on read, so later mutations by the caller do not affect the stored value.
- Not persisted. Data is discarded when the process ends.

:::tip
To change how values are cloned, replace it with the `clone` option. The default is `structuredClone`.
:::

Install with the following command.

```package-install
npm install @unikvs/memory
```

## Usage [#usage]

`Memory` implements IStorage. Pass it to UniKvs via persist().

```ts
import { Memory } from "@unikvs/memory";
```

The constructor arguments are as follows.

<TypeTable
  type={{
    options: {
      type: "MemoryOptions",
      description:
        "Settings for the cloning method and repair-write permission. Uses defaults when omitted.",
    },
    "options.clone": {
      type: "<T>(value: T) => T",
      default: "structuredClone",
      description: "Function used for cloning on save and on read.",
    },
    "options.allowRepair": {
      type: "boolean",
      default: "false",
      description: "Whether to allow writes via repair.",
    },
  }}
/>

Below is an example of saving a value and reading it back.

```ts
import { Memory } from "@unikvs/memory";
import { UniKvs, type Value } from "unikvs";

const kvs = UniKvs.config<{
  greeting: Value<string>;
}>()
  .persist(new Memory())
  .create();

await kvs.open();

await kvs.set("greeting", "hello");
const greeting = await kvs.get("greeting");

await kvs.close();
```

## Data types [#data-types]

| Operation                           | Supported data type                                                               |
| ----------------------------------- | --------------------------------------------------------------------------------- |
| `write`・`read`                     | Arbitrary values (strings, objects, `null`, `undefined`, `Uint8Array`, and so on) |
| `getWritable`・`getReadable` chunks | `Uint8Array<ArrayBuffer>`                                                         |

- `write` and `read` support arbitrary values such as strings, objects, `null`, `undefined`, and `Uint8Array`, and store them as-is.
- Values are cloned with `clone` on write and on read. The default is `structuredClone`.
- `write`, `read`, `exists`, `delete`, and `clear` are all synchronous.
- Stream operations only support `Uint8Array<ArrayBuffer>`.
- `getWritable` buffers chunks internally and joins them into the stored value on `close`. The save is not finalized until `close`.
- `getReadable` emits the stored value as a single chunk.

## Errors [#errors]

This package throws the following errors.

### KeyNotFoundError

#### Meaning

The specified key does not exist. A shared error from `@unikvs/core`.

#### How to handle

Check with `exists` before reading, or verify the key spelling.

#### Example

Below is an example of catching `KeyNotFoundError`.

```ts
import { KeyNotFoundError, Memory } from "@unikvs/memory";

const storage = new Memory();

try {
  storage.read({ key: "unknown" });
} catch (error) {
  if (error instanceof KeyNotFoundError) {
    console.log(error.meta.key);
  } else {
    throw error;
  }
}
```

### InvalidChunkTypeError

#### Meaning

The chunk type is not `Uint8Array<ArrayBuffer>`. Caused by passing a non-`Uint8Array` value on write, or by reading a non-byte value with `getReadable`. Includes `key`, `chunk`, and `chunkType` in `meta`.

#### How to handle

Only pass `Uint8Array<ArrayBuffer>` through streams, and store byte values under keys read via streams.

#### Example

Below is an example of catching `InvalidChunkTypeError`.

```ts
import { InvalidChunkTypeError, Memory } from "@unikvs/memory";

const storage = new Memory();
storage.write({ key: "greeting", data: "hello", vars: {} });

const reader = storage.getReadable({ key: "greeting" }).getReader();

try {
  await reader.read();
} catch (error) {
  if (error instanceof InvalidChunkTypeError) {
    console.log(error.meta.chunkType);
  } else {
    throw error;
  }
}
```

### RepairNotAllowedError

#### Meaning

A write via repair (`repair`) is not allowed. Includes `name` in `meta`. A shared error from `@unikvs/core`.

#### How to handle

Recreate the instance with `allowRepair: true`, or avoid repair writes in your workflow.

#### Example

Below is an example of catching `RepairNotAllowedError`.

```ts
import { RepairNotAllowedError } from "@unikvs/core";
import { Memory } from "@unikvs/memory";

const storage = new Memory();

try {
  storage.write({ key: "k1", data: "v1", vars: { "unikvs:repair": true } });
} catch (error) {
  if (error instanceof RepairNotAllowedError) {
    console.log(error.meta.name);
  } else {
    throw error;
  }
}
```
