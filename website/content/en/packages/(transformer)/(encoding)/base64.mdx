## Overview [#overview]

`@unikvs/base64` is a Transformer plugin that converts byte sequences to bytes representing standard base64 strings. <Badge>Transformer</Badge>

Use it for storing into destinations that only hold text, or for passing binary data as ASCII strings.

- The 64 characters used are RFC 4648 §4 `A-Z`, `a-z`, `0-9`, `+`, and `/`.
- It is always open. No `open` or `close` is needed; `isOpen` always returns `true` and `name` always returns `"Base64"`.
- It runs on Node.js, Bun, and browsers with no runtime-specific behavior differences.

:::tip
`+`, `/`, and `=` may be interpreted as delimiters in URLs or file names. For values embedded in URLs, use [`@unikvs/base64url`](/packages/base64url).
:::

Install with the following command.

```package-install
npm install @unikvs/base64
```

## Usage [#usage]

`Base64` implements ITransformer. Pass it to UniKvs via transform().

```ts
import { Base64 } from "@unikvs/base64";
```

The constructor arguments are as follows.

<TypeTable
  type={{
    options: {
      type: "Base64Options",
      description: "Settings for encoding and padding. Runs with defaults when omitted.",
    },
    "options.encoder": {
      type: "FastUtf8",
      description: "The encoder that converts base64 text to bytes. Specify it only when you need a replacement.",
    },
    "options.decoder": {
      type: "FastUtf8",
      description: "The decoder that converts bytes to base64 text. Specify it only when you need a replacement.",
    },
    "options.padding": {
      type: "boolean",
      default: "true",
      description: "Whether to append `=` at the end. `decode` accepts input with or without it.",
    },
  }}
/>

Below is an example of saving a written value as base64 and restoring it to the original bytes on read.

```ts
import { Base64 } from "@unikvs/base64";
import { Memory } from "@unikvs/memory";
import UniKvs, { type PlainValue } from "unikvs";

const kvs = UniKvs.config<{ data: PlainValue<Uint8Array<ArrayBuffer>> }>()
  .transform(new Base64())
  .persist(new Memory())
  .create();

await kvs.open();

const input = new TextEncoder().encode("foobar");
await kvs.set("data", input);

const output = await kvs.get("data");

await kvs.close();
```

## Data Types [#data-types]

| Method | Input | Output |
| --- | --- | --- |
| `encode` | `Uint8Array<ArrayBuffer>` | `Uint8Array<ArrayBuffer>` |
| `decode` | `Uint8Array<ArrayBuffer>` | `Uint8Array<ArrayBuffer>` |
| `getEncodable` | `Uint8Array<ArrayBuffer>` | `Uint8Array<ArrayBuffer>` |
| `getDecodable` | `Uint8Array<ArrayBuffer>` | `Uint8Array<ArrayBuffer>` |

- `encode` converts bytes to bytes (UTF-8) representing RFC 4648 §4 base64 text.
- `decode` restores bytes representing base64 text to the original bytes.
- The converted size is about 1.37 times the original size.
- With `padding: true` (default) it outputs the canonical form padded with `=`; with `padding: false` it omits trailing `=`.
- Empty input produces empty output.

- Chunks are simply concatenated with no delimiter.
- `getEncodable` converts in 3-byte units, holding a remainder (1–2 bytes) spanning chunk boundaries internally and joining it with the next chunk.
- Whether trailing `=` is present is determined when the stream ends.
- `getDecodable` restores in 4-character units, holding incomplete characters internally and joining them with the next chunk.
- An empty stream and zero-length chunks produce no values.

## Errors [#errors]

This package throws the following errors.

### Base64DecodeError

#### Meaning

The input cannot be interpreted as base64. Caused by stray `-`, `_`, or whitespace, misplaced `=`, or a length with remainder 1 when divided by 4.

#### How to handle

Check that the input is a run of base64 characters (`A-Z`, `a-z`, `0-9`, `+`, `/`, and trailing `=`). When you need a base64url value, convert it on the caller side or use `@unikvs/base64url`.

#### Example

Below is an example of catching `Base64DecodeError`.

```ts
import { Base64, Base64DecodeError } from "@unikvs/base64";

const base64 = new Base64();

try {
  base64.decode({ data: new TextEncoder().encode("ab-c") });
} catch (error) {
  if (error instanceof Base64DecodeError) {
    console.log("Cannot be interpreted as base64.");
  } else {
    throw error;
  }
}
```

Bytes that are invalid as UTF-8 propagate as a native `TypeError`, not as `Base64DecodeError`.

### Base64InvalidPaddingError

#### Meaning

`padding` is not a boolean. `meta` contains `actual`.

#### How to handle

Specify `true` or `false` for `padding`, or omit it to use the default.
