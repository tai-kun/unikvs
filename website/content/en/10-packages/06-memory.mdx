## Overview [#overview]

`@unikvs/memory` is a storage plugin that keeps data in memory. As its package description states, it stores arbitrary data in memory.

The main features are as follows.

- Because data is stored in memory, reads and writes complete synchronously.
- You can store arbitrary values such as strings and objects.
- It runs in any environment where `Map`, `structuredClone`, and Web Streams are available, such as Node.js and browsers.
- It is well suited as a test double or a temporary cache.

:::tip
No open step is required, and reads and writes complete synchronously, so it is well suited as a test double or a temporary cache.
:::

Install it with the following command.

```package-install
npm i @unikvs/memory
```

## Usage [#usage]

`Memory` is a storage class that implements `IStorage`. To use it as a `UniKvs` backend, pass it to `appendStorage()`.

You can also operate it directly on its own.

<Tabs>
  <Tab title="Via UniKvs">

```ts
import { Memory } from "@unikvs/memory";
import { UniKvs, type Value } from "unikvs";

const kvs = UniKvs.config<{
  foo: Value<string>;
}>()
  .appendStorage(new Memory())
  .create();
```

  </Tab>
  <Tab title="Standalone">

```ts
import { Memory } from "@unikvs/memory";

const storage = new Memory();
storage.write({ key: "k1", data: "v1" });
const value = storage.read({ key: "k1" });
```

  </Tab>
</Tabs>

The constructor arguments are as follows.

| Argument | Type | Required | Description |
| --- | --- | --- | --- |
| `options` | `MemoryOptions` | No | Initialization options. When omitted, it behaves as if an empty object was passed. |
| `options.clone` | `<T>(value: T) => T` | No | Function used to clone data. Defaults to `structuredClone`. |

The following example changes how values are cloned.

```ts
import { Memory } from "@unikvs/memory";

const storage = new Memory({
  clone: (value) => value,
});
```

The `open` and `close` methods are not implemented. The `isOpen` property always returns `true`, so no open or teardown step is required.

Basic operations look like this.

```ts
import { Memory } from "@unikvs/memory";

const storage = new Memory();

storage.write({ key: "k1", data: { message: "hello" } });

if (storage.exists({ key: "k1" })) {
  const value = storage.read({ key: "k1" });
  console.log(value);
}

storage.delete({ key: "k1" });
storage.clear();
```

`write`, `read`, `exists`, `delete`, and `clear` are all synchronous methods. `write` and `clear` return nothing. `read` returns the stored value. `exists` returns a boolean.

## Supported Data [#data]

`write` and `read` accept arbitrary values, not just byte sequences. You can store strings, objects, `null`, `undefined`, `Uint8Array`, and more as-is.

Values are cloned with the `clone` function both when stored and when retrieved. With the default `structuredClone`, mutating the original object after writing does not affect the stored value. Likewise, mutating a retrieved value does not affect the stored value.

Stream operations support only `Uint8Array<ArrayBuffer>`.

- `getWritable` buffers written chunks in an in-memory array and concatenates them into a single `Uint8Array` when the stream closes.
- `getReadable` emits the stored value as a single chunk. Reading fails if the stored value is not a `Uint8Array`.

:::note
Streams are not a native feature; they are implemented by concatenating chunks and emitting a single chunk. `getWritable` buffers written chunks in an in-memory array and concatenates them on close. `getReadable` emits the stored value as a single chunk.
:::

Stream usage looks like this.

```ts
import { Memory } from "@unikvs/memory";

const storage = new Memory();

// Write example
const writable = storage.getWritable({ key: "s1" });
const writer = writable.getWriter();
await writer.write(new Uint8Array([1, 2]));
await writer.write(new Uint8Array([3]));
await writer.close();

// Read example
const readable = storage.getReadable({ key: "s1" });
const reader = readable.getReader();
const result = await reader.read();
console.log(result.value);
```

## Limitations [#limitations]

- Data is not persisted. It is kept only while the application runs and is discarded when the process exits.
- Data is held in an internal `Map`. Storing large amounts of data or large binaries increases memory usage. Remove unneeded data with `delete` or `clear`.
- The default clone function is `structuredClone`. To store values that cannot be cloned, pass a custom function via the `clone` option.
- Streams are not a native feature; they are implemented by concatenating chunks and emitting a single chunk. They are not suited for streaming large datasets incrementally.

Data is not persisted. It is kept only while the application runs and is discarded when the process exits.
:::

## Errors [#errors]

This package defines the following errors.

| Error | Error name | When thrown |
| --- | --- | --- |
| `KeyNotFoundError` | `MemoryKeyNotFoundError` | Thrown when the key passed to `read`, `delete`, or `getReadable` does not exist. |
| `InvalidChunkTypeError` | `MemoryInvalidChunkTypeError` | Thrown when a non-`Uint8Array<ArrayBuffer>` value is written to the stream returned by `getWritable`, or when `getReadable` reads a key whose stored value is not a `Uint8Array`. |

The metadata for each error is as follows.

<Accordion>
  <AccordionItem title="KeyNotFoundError">

Holds `key`. The Japanese message is「キー \{key\} が見つかりません」.

  </AccordionItem>
  <AccordionItem title="InvalidChunkTypeError">

Holds `key`, `chunk`, and `chunkType`. `chunkType` is set automatically inside the constructor. The Japanese message is as follows.

```txt
キー {key} のチャンク型に Uint8Array<ArrayBuffer> を期待しましたが、{chunkType} を得ました
```

  </AccordionItem>
</Accordion>

Error handling looks like this.

```ts
import { KeyNotFoundError, Memory } from "@unikvs/memory";

const storage = new Memory();

try {
  storage.read({ key: "unknown" });
} catch (error) {
  if (error instanceof KeyNotFoundError) {
    console.log(error.meta.key);
  } else {
    throw error;
  }
}
```

`KeyNotFoundError` and `InvalidChunkTypeError`, along with their related metadata types, can be imported from `@unikvs/memory`.

## Examples [#examples]

A minimal working example is shown below.

```ts
import { Memory } from "@unikvs/memory";

const storage = new Memory();

storage.write({ key: "greeting", data: "hello" });
console.log(storage.exists({ key: "greeting" }));
console.log(storage.read({ key: "greeting" }));
storage.delete({ key: "greeting" });
console.log(storage.exists({ key: "greeting" }));
```
