## Overview [#overview]

`@unikvs/memory` is a storage plugin that keeps data in memory. It stores arbitrary data as is.

- Reads and writes complete synchronously; no `open` or `close` is needed.
- You can store arbitrary values such as strings and objects.
- It runs where `Map`, `structuredClone`, and Web Streams are available.
- It suits test doubles and temporary caches.

Install it with the following command.

```package-install
npm i @unikvs/memory
```

## Usage [#usage]

`Memory` implements `IStorage`. Pass it to `appendStorage()` for `UniKvs`, or operate it directly.

<Tabs>
  <Tab title="Via UniKvs">

```ts
import { Memory } from "@unikvs/memory";
import { UniKvs, type Value } from "unikvs";

const kvs = UniKvs.config<{
  foo: Value<string>;
}>()
  .appendStorage(new Memory())
  .create();
```

  </Tab>
  <Tab title="Standalone">

```ts
import { Memory } from "@unikvs/memory";

const storage = new Memory();
storage.write({ key: "k1", data: "v1" });
const value = storage.read({ key: "k1" });
```

  </Tab>
</Tabs>

The constructor arguments are as follows.

| Argument | Type | Required | Description |
| --- | --- | --- | --- |
| `options` | `MemoryOptions` | No | When omitted, behaves as an empty object. |
| `options.clone` | `<T>(value: T) => T` | No | Function used to clone data. Defaults to `structuredClone`. |

The following example changes how values are cloned.

```ts
import { Memory } from "@unikvs/memory";

const storage = new Memory({
  clone: (value) => value,
});
```

`open` and `close` are not implemented. `isOpen` always returns `true`.

```ts
import { Memory } from "@unikvs/memory";

const storage = new Memory();

storage.write({ key: "k1", data: { message: "hello" } });

if (storage.exists({ key: "k1" })) {
  const value = storage.read({ key: "k1" });
  console.log(value);
}

storage.delete({ key: "k1" });
storage.clear();
```

`write`, `read`, `exists`, `delete`, and `clear` are all synchronous.

## Supported Data [#data]

`write` and `read` accept arbitrary values, not just bytes. You can store strings, objects, `null`, `undefined`, `Uint8Array`, and more as-is.

Values are cloned with `clone` on store and retrieval. With the default `structuredClone`, mutating the original after writing leaves the stored value unaffected, and vice versa.

Stream operations support only `Uint8Array<ArrayBuffer>`. They use chunk concatenation and single-chunk emission, not native streaming.

- `getWritable` buffers chunks in a memory array and concatenates them into a single `Uint8Array` on close.
- `getReadable` emits the stored value as a single chunk. Reading fails if the value is not a `Uint8Array`.

Stream usage looks like this.

```ts
import { Memory } from "@unikvs/memory";

const storage = new Memory();

// Write example
const writable = storage.getWritable({ key: "s1" });
const writer = writable.getWriter();
await writer.write(new Uint8Array([1, 2]));
await writer.write(new Uint8Array([3]));
await writer.close();

// Read example
const readable = storage.getReadable({ key: "s1" });
const reader = readable.getReader();
const result = await reader.read();
console.log(result.value);
```

## Limitations [#limitations]

- Data is not persisted. It is discarded when the process exits.
- Data is held in an internal `Map`. Large volumes increase memory usage. Remove unneeded data with `delete` or `clear`.
- The default clone function is `structuredClone`. For unclonable values, pass a custom `clone` function.
- Streams use chunk concatenation. They do not suit incremental processing of large data.

## Errors [#errors]

| Error | Error name | When thrown |
| --- | --- | --- |
| `KeyNotFoundError` | `MemoryKeyNotFoundError` | Thrown when the key for `read`, `delete`, or `getReadable` does not exist. |
| `InvalidChunkTypeError` | `MemoryInvalidChunkTypeError` | Thrown for non-`Uint8Array<ArrayBuffer>` writes, or reads of a key whose value is not a `Uint8Array`. |

The metadata for each error is as follows.

<Accordion>
  <AccordionItem title="KeyNotFoundError">

Holds `key`. The Japanese message is「キー \{key\} が見つかりません」.

  </AccordionItem>
  <AccordionItem title="InvalidChunkTypeError">

Holds `key`, `chunk`, and `chunkType`. `chunkType` is set automatically. The Japanese message is as follows.

```txt
キー {key} のチャンク型に Uint8Array<ArrayBuffer> を期待しましたが、{chunkType} を得ました
```

  </AccordionItem>
</Accordion>

```ts
import { KeyNotFoundError, Memory } from "@unikvs/memory";

const storage = new Memory();

try {
  storage.read({ key: "unknown" });
} catch (error) {
  if (error instanceof KeyNotFoundError) {
    console.log(error.meta.key);
  } else {
    throw error;
  }
}
```

## Examples [#examples]

A minimal example is shown below.

```ts
import { Memory } from "@unikvs/memory";

const storage = new Memory();

storage.write({ key: "greeting", data: "hello" });
console.log(storage.exists({ key: "greeting" }));
console.log(storage.read({ key: "greeting" }));
storage.delete({ key: "greeting" });
console.log(storage.exists({ key: "greeting" }));
```
