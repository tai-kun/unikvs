## Comparison table [#comparison]

| Feature | `@unikvs/memory` | `@unikvs/fs.node` | `@unikvs/s3.node` | `@unikvs/opfs` | `@unikvs/indexeddb` |
| --- | --- | --- | --- | --- | --- |
| Environment | <Badge>All</Badge> | <Badge variant="accent">Node.js</Badge> | <Badge variant="accent">Node.js</Badge> | <Badge variant="warning">Browser</Badge> | <Badge variant="warning">Browser</Badge> |
| Persistence | None. | Yes. | Yes. | Yes. | Yes. |
| Supported data | Any value. | Bytes. | Bytes. | Bytes. | Any value. |
| Streams | Limited. | Supported. | Supported. | Supported. | Check limitations. |
| Primary use | Test / temporary. | Single server. | Shared / large-scale. | Large-scale browser. | Structured browser. |

See each package reference for details.

## Selection guide [#guide]

<Tabs>
  <Tab title="Test / temporary">
    Use memory. It is the simplest and works everywhere.
  </Tab>
  <Tab title="Single server">
    Use files. Minimal setup, good for small to medium data.
  </Tab>
  <Tab title="Shared / large-scale">
    Use S3-compatible storage. It supports multipart transfers.
  </Tab>
  <Tab title="Browser">
    Use OPFS for large bytes, and IndexedDB for structured data such as strings and objects.
  </Tab>
</Tabs>

## Environment notes [#environments]

:::warning
Node.js-only packages don't work in browsers, and browser-only packages don't work in Node.js. To share code, build clients per environment.
:::

- Persistent storages need capacity, permission, and network planning. See each package reference for details.
