## Overview [#overview]

Middleware that hashes byte sequences and verifies them against expected values.<Badge>Middleware</Badge>

It passes data through unchanged and only verifies when a checksum var holds an expected hash. Six variants exist: MD5, SHA-1, SHA-224, SHA-256, SHA-384, and SHA-512.

- Each concrete class's `name` matches the class name (e.g. `"ChecksumSha256"`).
- `isOpen` is always `true`.

Install with:

```package-install
npm install @unikvs/checksum @noble/hashes@2.0.0
```

## Usage [#usage]

ChecksumSha256 implements IMiddleware. Pass it to UniKvs with use().

```ts
import { ChecksumSha256 } from "@unikvs/checksum";
```

The other five work the same way. Constructor arguments:

<TypeTable
  type={{
    required: {
      type: "[#checksum-required] boolean",
      description: "Whether to throw when no checksum var is present. Defaults to `false`.",
    },
  }}
/>

The following stores data with an expected SHA-256 hash and verifies it on reads:

```ts
import { ChecksumSha256 } from "@unikvs/checksum";
import { Memory } from "@unikvs/memory";
import * as unikvs from "unikvs";

const kvs = new unikvs.Builder<{ file: unikvs.Value<Uint8Array> }>()
  .use(new ChecksumSha256())
  .persist(new Memory())
  .build();

await kvs.open();

const data = new TextEncoder().encode("abc");
const sha256 = "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad";

await kvs.set("file", data, {
  vars: { "@unikvs/checksum:sha256": sha256 },
});
const file = await kvs.get("file", {
  vars: { "@unikvs/checksum:sha256": sha256 },
});
await kvs.close();
```

### `Checksum` [#checksum]

Abstract base class for the six variants. Never use it directly; use a concrete class.

`CHECKSUM_ON_HASH_VAR_NAME` is the name of the callback var that receives the computed hash and a snapshot of the runtime variables. Its value is `CHECKSUM_VAR_NAME` followed by `:onHash`.

### `ChecksumOnHash` [#checksum-on-hash]

Callback that receives the computed hash and a snapshot of the runtime variables. Pass a function in the `"<CHECKSUM_VAR_NAME>:onHash"` var, separate from the checksum var. For SHA-256, that is `"@unikvs/checksum:sha256:onHash"`.

The callback is called when hashing and verification succeed. If you specify only the callback without an expected checksum, the middleware still computes the hash and calls the callback. If `required` is `true` and no expected checksum is present, it throws `ChecksumRequiredError` and does not call the callback.

The second argument is a snapshot of the runtime variables at call time ([`VariablesSnapshot`](/packages/core/pipeline-context#variables-snapshot)). The snapshot is a shallow copy; object values share the same references.

The following example receives the SHA-256 hash and runtime variables during a write.

```ts
const hashes: string[] = [];

await kvs.set("file", data, {
  vars: {
    region: "us-east-1",
    "@unikvs/checksum:sha256:onHash": (
      hash: string,
      variables: ReadonlyMap<string, unknown>,
    ): void => {
      hashes.push(hash);
      console.log(variables.get("region"));
    },
  },
});
```

If the callback value is not a function, the middleware throws `ChecksumInvalidOnHashError`. Exceptions or rejections thrown by the callback propagate as operation failures.

:::note[Call timing]
The callback is called when hash computation completes. It does not guarantee that the storage write has completed. For streams, it is called when the stream ends.
:::

## Data types [#data-types]

| Method         | Input                     | Output                    |
| -------------- | ------------------------- | ------------------------- |
| `encode`       | `Uint8Array<ArrayBuffer>` | `Uint8Array<ArrayBuffer>` |
| `decode`       | `Uint8Array<ArrayBuffer>` | `Uint8Array<ArrayBuffer>` |
| `encodeStream` | `Uint8Array<ArrayBuffer>` | `Uint8Array<ArrayBuffer>` |
| `decodeStream` | `Uint8Array<ArrayBuffer>` | `Uint8Array<ArrayBuffer>` |

- `encode` and `decode` pass data through unchanged.
- This middleware computes the hash (lowercase hex) when the matching checksum var holds a string or when the `onHash` callback is specified.
- It throws when the value does not match the expectation.
- It throws when no checksum var exists and `required` is `true`, even if the `onHash` callback is specified.
- The `onHash` callback receives the computed hash (lowercase hex) and a snapshot of the runtime variables. If the callback returns a `Promise`, the middleware waits for it.
- `encodeStream` and `decodeStream` stream chunks downstream unchanged while updating the hash, verifying on completion, and calling the `onHash` callback.

## Errors [#errors]

Errors thrown by this package:

### `ChecksumMismatchError` [#error-checksum-mismatch]

Thrown when the computed hash does not match the expectation.

<TypeTable
  type={{
    actual: {
      type: "[#checksum-mismatch-actual] string",
      required: true,
      description: "Computed hash (lowercase hex).",
    },
    expected: {
      type: "[#checksum-mismatch-expected] string",
      required: true,
      description: "Expected hash from the checksum var.",
    },
  }}
/>

#### Meaning

Either the data or the expectation is wrong.

#### How to fix

Check which of the data and the expected hash is correct.

### `ChecksumRequiredError` [#error-checksum-required]

#### Meaning

Thrown when `required` is `true` but no checksum var was given.

#### How to fix

Set the expected hash in the matching checksum var, or set `required` to `false`.

### `ChecksumInvalidVarNameError` [#error-checksum-invalid-var-name]

Thrown when a checksum var name is not a string.

<TypeTable
  type={{
    actual: {
      type: "[#checksum-invalid-var-name-actual] unknown",
      required: true,
      description: "The given var-name value.",
    },
  }}
/>

#### Meaning

This is a usage error, so it extends `InvalidUsageErrorBase`. `meta.actual` keeps the given value as-is.

#### How to fix

This never happens when using the published concrete classes as-is. In a custom subclass, set `CHECKSUM_VAR_NAME` to a string.

### `ChecksumInvalidOnHashError` [#error-checksum-invalid-on-hash]

Thrown when the `"<CHECKSUM_VAR_NAME>:onHash"` value is not a function.

<TypeTable
  type={{
    actual: {
      type: "[#checksum-invalid-on-hash-actual] unknown",
      required: true,
      description: "The given callback value.",
    },
  }}
/>

#### Meaning

This is a usage error, so it extends `InvalidUsageErrorBase`. `meta.actual` keeps the given value as-is.

#### How to fix

Set a function in the `onHash` var, or omit the var.

### `ChecksumInvalidRequiredError` [#error-checksum-invalid-required]

Thrown when `required` is not a boolean.

<TypeTable
  type={{
    actual: {
      type: "[#checksum-invalid-required-actual] unknown",
      required: true,
      description: "The given `required` value.",
    },
  }}
/>

#### Meaning

This is a usage error, so it extends `InvalidUsageErrorBase`. `meta.actual` keeps the given value as-is.

#### How to fix

Pass `true` or `false` to `required`. It defaults to `false`.
